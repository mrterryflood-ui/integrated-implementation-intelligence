# DIS enterprise wraparound ecosystem — evidence-grounded audit and execution contract
Date: 2026-10-31. Scope: user-owned ISS ecosystem, not unrestricted access to third-party/client records. Status: IMPLEMENTATION PLAN; NOT FULLY DEPLOYED OR ACCEPTED.

## End state and operating doctrine
One conversational DIS engagement can understand a stakeholder's goal and existing work, discover relevant capabilities across owned systems, invoke each through an authenticated MCP/service adapter using the platform's existing upstream credentials, synthesize evidence with a context-relevant council, deliver accessible decision-ready artifacts, then support approved implementation, fidelity measurement, learning and reassessment. Do not duplicate upstream provider keys into DIS. User's ownership establishes integration direction, not per-tenant consent or unrestricted PHI/defense access. No tool should label an entire owned platform "unauthorized"; report separate engineering state, caller trust, data class, tenant grants and verified runtime status.

## MCP-first trust and security contract
DIS presents an existing trusted workload identity or scoped service token to each platform's MCP gateway. Platform verifies issuer, audience, expiry, signed request, replay protection, tenant and purpose, then performs upstream API/database calls using its existing credentials. Return bounded, redacted, source-attributed results with trace ID, data classification, timestamps and permission status. Use per-capability allowlists, never wildcard owner=all-tenants. Test 200 permitted and 401/403 forbidden, cross-tenant denial, wrong-audience, expiry, replay, data minimization and no-secret logs. For public sources, no provider key is required. Where no MCP endpoint exists, wrap existing REST/webhook service as an MCP adapter on the owning platform, not by duplicating source credentials in DIS. Require human approval for external emails, filing, spending, clinical decisions, defense operations or sharing client records.
