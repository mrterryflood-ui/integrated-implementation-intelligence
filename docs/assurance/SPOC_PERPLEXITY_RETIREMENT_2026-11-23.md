Before: both copies defaulted to `pplx` in the API and CLI. `fetch_url` tried
`pplx_sdk.content.fetch` even when a different LLM backend had been selected. Selecting `pplx`
could also call `pplx_sdk.llm.extract`. No actual manual invocation or billed use was established.

Changed: remove both SDK paths, make the default the existing local Ollama endpoint/model,
and preserve explicitly selected OpenAI-compatible extraction. Reject known retired backend,
endpoint and model names before source acquisition or database mutation, and again immediately
before transport. Matching includes case, Unicode normalization and up to three URL-decoding
passes; it does not discover arbitrary hidden proxy aliases. Invalid environment defaults fail
explicitly. No failed route automatically switches providers.

Source URLs use the existing direct `requests` acquisition path with HTTP error checks and basic
HTML-tag removal. Declared text/HTML and textual JSON/XML types are accepted; missing/unsupported
types and detected PDF/NUL binary content fail before extraction, including for a paid route.
An extracted UTF-8 `--file` is the explicit alternative; no binary parser is added.
Source and model redirects are disabled and 3xx responses fail visibly. The
operator must select a final permitted URL. Unknown title/publication date remain unknown.
OpenRouter host-specific requests disable the web plugin and reject its `:online` shortcut;
ordinary OpenAI-compatible requests receive no unsupported plugin field. No server tools are
requested. The quote-presence explanation now states its real limit: the quote can exist without
supporting the claimed fact.
